# AIFX: 為替予測サーバー

主要7通貨ペア (USD/JPY, EUR/JPY, GBP/JPY, AUD/JPY, EUR/USD, GBP/USD, AUD/USD) の値動きを予測し続けるサーバーです。

- **予測はサーバーで計算します。** Webページはサーバーが公開するAPI (JSON) を表示するだけで、計算はしません。
- **予測は結果が出る前に台帳へ記録します。** 対象時刻が来たら自動で判定し、的中率・誤差・予測レンジの的中率を公開します。
- **自分の成績から学習します。** 判定済みの結果だけを使って、モデルの重み・信号の採用率・レンジの幅・ニュースの効き方を調整します。
- **ニュースと経済指標を自動で集めて分析します。** 各通貨への影響を判定し、予測と予測レンジに反映します。
- **成績をごまかせないようにしています。** 台帳はハッシュ鎖で改ざんを検出でき、先読みや判定の飛ばしはプログラムで自動検査します。

## 仕組み

```
      ┌──────────── サーバー (GitHub Actions 15分ごと / aifx serve) ────────────┐
      │ 1. 価格 (15分足・1時間足・日足)・ニュース・経済指標を取得                  │
      │ 2. 生データを追記専用ファイルに保存し、そのハッシュを台帳に記録              │
      │ 3. 対象時刻を過ぎた予測を判定 (結果を台帳に記録)                            │
      │ 4. 判定済みの結果から学習                                                   │
      │ 5. 新しい予測を発行 (台帳に記録)                                            │
      │ 6. 保存済みの価格でバックテストを更新 (新しい時点を追加)                    │
      │ 7. 台帳全体を検証し、抜き取りで予測を再計算                                 │
      │ 8. API (JSON) を書き出す                                                    │
      └──────────────────────────────┬────────────────────────────────────────────┘
                                     │ api/meta.json, api/pair/USDJPY.json, api/backtest.json …
                              ┌──────┴──────┐
                              │  Webページ   │  表示のみ。1分ごとに更新を確認
                              └─────────────┘
```

### 予測の種類

| 種類 | 起点 | 予測する時点 | 判定 |
|---|---|---|---|
| 超短期 (15分足) | 15分ごと、確定した15分足の終値 | 15分・1時間・4時間後 (15分足1・4・16本) | その時刻に確定していた15分足の終値 |
| 短期 (1時間足) | 毎時、確定した1時間足の終値 | 1・4・24時間後 (市場が開いている時間で数える) | その時刻に確定していた1時間足の終値 |
| 中期 (日足) | 毎日、確定した日足 (ロンドン時間の0時) | 1・5・10・20営業日後 | 同上 (1時間足) |

各予測には、中心値・20/40/50/60/80/95%の予測レンジ・上昇確率・価格の分布が付きます。予測は次の足が確定する前に発行したものだけが有効で、サーバーの処理が遅れて次の足が確定してしまった場合、その起点の予測は出しません。

### モデルと学習

6つのモデル (ランダムウォーク、ドリフト、指数平滑、自己回帰、リッジ回帰、パターン類似) の予測を組み合わせ、次の4つを実績から学習します。設定値は、下記の「過去データによる検証」で古い期間だけを使って選び、新しい期間で効果を確かめたものです。

| 学習する値 | 意味 |
|---|---|
| モデルの重み | 誤差の小さいモデルを重く使う |
| 信号の採用率 (gain) | モデルの方向予測にどこまで従うか。過去の実績で有効性が示されない限り0に近く、予測は「変化なし」寄りになる |
| レンジ補正 (k) | 80%レンジに実際の値が約80%入るよう幅を調整 |
| ニュース係数 (β) | ニュース信号で予測をどれだけ動かすか |

学習には、予測の時点で判定が済んでいた結果だけを使います。始めは、各時点までのデータだけで行った過去データの検証 (ウォークフォワード) を事前情報にし、実績がたまるほど実績の比重が大きくなります。

予測レンジは次のように作ります。

- **15分足:** 各15分足の高値・安値の幅から値動きの大きさを測り、時間帯ごとの違い (1時間単位で推定)、週末、重要指標の発表予定を反映します。設定は直近約60日分の15分足で選び、後半の期間で確認しました (下記)。
- **1時間足:** 各1時間足の高値・安値の幅から値動きの大きさを測り、時間帯ごとの違い (東京・ロンドン・ニューヨーク)、週末の窓開けリスク、重要指標の発表予定を反映します。
- **日足:** 1時間足から各日の値動きの大きさ (実現ボラティリティ) を測ります。1時間足が足りない日は日足の変化を使います。
- **レンジの形:** 為替の値動きは正規分布より裾が太い (大きな動きが起きやすい) ため、t 分布の形にしています。80%レンジの幅は実績で補正し、50%・95%レンジはこの形に従います。

### ニュース分析

- 取得元: Google ニュース検索 (日本語・英語の為替・中央銀行・米国指標・地政学)、FRB・ECB・日銀・英中銀・豪中銀の発表、ForexLive、Forex Factory の経済指標カレンダー
- 見出しごとに、USD・JPY・EUR・GBP・AUD それぞれへの影響 (−1 通貨安 〜 +1 通貨高) をキーワード分析 (日本語・英語) で判定します。分析はすべてサーバー内で行い、有料のAPIや外部の分析サービスは使いません。判定根拠となる語句は `aifx/news.py` で確認・調整できます。
- 「利上げ観測が後退」「利下げを急がず」「rate cut bets fade」「no rush to cut」のような否定・後退の表現は向きを反転させます。「ドル売り」「円買い」などの売買の表現や、「過度な変動をけん制」のような口先介入も判定します。
- 複数のサイトに配信された同じ記事は、見出しの文字の重なりでまとめ、1本として数えます (同じ記事が5サイトに載っても5倍にはなりません)。
- 通貨ごとの「ニュース圧力」は、新しい見出しほど重く (半減期 約8時間) 平均した値です。ペアの信号は「基軸通貨の圧力 − 決済通貨の圧力」です。
- 予測に使えるのは、**予測の起点時刻より前に取得・保存済みの見出しだけ**です。

ニュースの取得先はすべて無料で公開されているRSSとカレンダーです。

## 成績をごまかせない仕組み

| ルール | どう守るか |
|---|---|
| 予測は結果が出る前に記録 | 予測は発行時に台帳へ追記。各記録は前の記録の SHA-256 ハッシュを含む (ハッシュ鎖) ので、書き換え・削除・並べ替えは検出される |
| 使ったデータを後から変えられない | 価格・ニュース・経済指標は追記専用ファイルに保存し、ローリングハッシュを台帳に記録 |
| 先読みしない | 予測に使えるのは起点時刻までに確定した価格と、起点時刻より前に保存済みのニュース・指標のみ。抜き取りで、当時のデータだけで予測を作り直し、同じ数字になるか確認 (`aifx audit`)。先読みしていれば一致しない |
| ニュースの取得時刻を偽れない | 各見出しの取得時刻は、それを保存したサイクルの時刻と一致しなければならない |
| 都合の悪い予測を判定から外せない | 対象時刻を過ぎ、データがそろった予測はすべて判定されていなければ検証エラー |
| 判定を早めたり、都合のよい価格を使えない | 判定は対象時刻の後、その時点で確定していた最新の足 (15分足の予測は15分足、それ以外は1時間足) の終値のみ |
| 対象時刻をずらせない | 対象時刻は取引カレンダーの規則どおりでなければ検証エラー |
| 数字を盛れない | 成績は常に「予測しない (ランダムウォーク)」と同じ予測で比較し、95%信頼区間・有意性 (二項検定、Diebold-Mariano 検定)・Brierスコアを表示 |
| 履歴を書き換えられない | 台帳は GitHub の `ledger` ブランチに追記のみで push (force push しない)。サイクルごとに、前回の先頭記録が変わっていないことを確認 |

誰でも次のコマンドで検証できます。

```bash
git clone https://github.com/nomixio260-a11y/aifx && cd aifx
pip install -e .
git fetch origin ledger && git worktree add state origin/ledger
aifx verify --state state                    # ハッシュ鎖・データ・時刻・判定漏れ
aifx audit --state state --sample 20         # 予測を当時のデータで再計算
aifx audit --state state --external          # 保存した価格を取得し直した価格と照合
```

同じモデルで作られた予測だけが再計算の対象です (モデルのコードが変わると、以前の予測は対象外として件数を表示)。

## Webで見る

画面は5つのタブに分かれています。スマホでは画面下のタブで切り替えます。

| タブ | 内容 |
|---|---|
| 予測 | 通貨ペアと足 (15分足・1時間足・日足) を選ぶと、選んだ予測先 (例: 24時間後) の「80%の確率で入る範囲」と上昇確率を文章とバーで表示し、その予測先のバックテスト成績も添えます。予測先ごとのレンジを同じ目盛りで比較できるカード、ローソク足と予測レンジのチャート (外側から95・80・60・40・20%の範囲を濃淡で表示し、予測先ごとに上限・中心・下限の価格を表示)、予想価格の分布、「この価格より上にある確率」の一覧、予測に使ったニュースと指標 |
| 市場分析 | 通貨の強さ (24時間・5日・20日) と過去5日の推移、値動きとニュースの向きが一致しているか、ペアごとの値動きの荒さ (過去1年の中での位置)・トレンドの状態、48時間以内の重要指標 |
| 実績 | 台帳に記録した予測の的中率、ランダムウォークとの比較、50/80/95%レンジの的中率、確率の信頼性。その下にバックテスト (全ペア・ペア別) の成績と推移 |
| ニュース | 通貨ごとのニュース圧力と推移、ペア別の信号、経済指標カレンダー、見出しと分析結果 (同じ記事はまとめて表示) |
| 検証 | 台帳の検証結果、抜き取り再計算、学習の状態、過去データによる検証の要約 |

チャートの「答え合わせ」では、ローソク足の後ろに、過去に出した予測がその時刻について示した50%・80%レンジを灰色の帯で重ね、実際の値が80%レンジに入った所を緑の点、外れた所を赤の◆で示します。台帳の予測がまだ少ないうちはバックテストの予測を表示します (切り替え可能)。

市場分析は値動きの「現在の状態」の説明で、予測ではありません。予想の分布と確率は、サーバーが予測と同じ分布 (t 分布) から計算したもので、Webページは表示するだけです。

- **GitHub Pages (自動更新):** リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にすると、`https://nomixio260-a11y.github.io/aifx/` にサーバーの最新結果が15分ごとに公開されます。
- **自分のサーバー:** 下記の `aifx serve` または Docker。ページ上の「今すぐ更新」でサーバーに更新を依頼できます。

## 使い方

```bash
pip install -e ".[dev]"

aifx serve --port 8000                  # サーバーとして常駐 (5分ごとに更新) し、http://127.0.0.1:8000/ で表示
aifx cycle --site site --audit 3        # 1回分の処理をして site/ にWebページとAPIを書き出す
aifx status                             # 最新の予測と実績をターミナルに表示
aifx verify                             # 台帳の検証
aifx audit --sample 10                  # 予測の再計算
aifx export --site site                 # 保存済みの状態からWebページとAPIを書き出す
aifx cycle --synthetic --site site      # ネットなしで動作確認 (乱数の相場)
aifx backtest                           # バックテストだけを更新 (通常はサイクルの中で自動実行)
aifx research                           # 過去データでの検証 (下記参照)
aifx research --intraday                # 15分足の検証
```

状態 (台帳・価格・ニュース) は `--state` (既定 `state/`) に保存されます。

## GitHub での運用

- `.github/workflows/server.yml` が15分ごとに1サイクルを実行し、台帳を `ledger` ブランチに追記して、Pages が有効ならWebページを公開します。デフォルトブランチへのコードの push でもすぐ実行されます。GitHub の定期実行は混雑時に遅れたり間引かれたりするため、15分足の予測は実行された回の分だけ発行されます。
- バックテストの計算結果は台帳ではなく派生データなので、Actions のキャッシュで実行間に引き継ぎ、毎回は新しい時点だけを計算します (キャッシュが消えても次の実行で作り直します)。
- `ledger` ブランチにブランチ保護 (force push の禁止) を設定すると、履歴の書き換えをGitHub側でも防げます。
- `.github/workflows/ci.yml` がテスト (不正の検出テストを含む) を実行します。

## 過去データによる検証

2002年からの日足 (7ペア) と直近約2年分の1時間足で、**各時点ではその時点までのデータだけで予測する**検証 (ウォークフォワード) を行い、結果を [research/report.md](research/report.md) にまとめています。台帳の実績とは別の、事前の検証です。

- 設定値や係数は古い期間 (日足は2002〜2016年、1時間足は前半6割) だけで決め、新しい期間 (日足は2017〜2026年、1時間足は後半4割) の成績で採否を判断しました。検証期間のデータは設定選びに使っていません。
- 金利差 (キャリー) には FRED の短期金利を使い、公表の遅れを考慮して当時知り得た値だけを使いました。
- 試した方法: 6モデルとその組合せ、金利差、モメンタム、時間帯の癖、直前の値動き、値動きの大きさの推定方法 (EWMA の設定、高値・安値の幅、1時間足からの実現ボラティリティ)、レンジの形 (正規分布・t 分布)。

**結果:**

| 対象 | 検証期間の結果 | 本番への反映 |
|---|---|---|
| 方向 (中心値) | どの方法も「変化なし」を有意に上回れず。6モデルの単純平均は有意に悪化 | 方向予測への追従を強く抑える (λ 11→50)。日足10〜20営業日先の悪化幅が約1/4に |
| 1時間足のレンジ | 高値・安値の幅を使うと 1・4時間先の CRPS が有意に改善 | 採用 |
| 日足のレンジ | 1時間足から測る実現ボラティリティで 1・5営業日先が有意に改善 | 採用 |
| レンジの形 | 50%レンジの的中 55%→52%、95%レンジ 93%→95% (1時間足) と名目値に近づく | t 分布を採用 |

さらに、予測レンジについて5つの案 (補正に使う実績の期間、上下で幅の違うレンジ、VIX による調整、週末・曜日の補正、時間帯ごとの変動の推定方法) も同じ手順で試しましたが、改善はどれも0.2%程度以下で、採用していません。

調整に使った期間で成績を測ると実力以上に見えます。例えば「時間帯ごとの値動きの癖」は、調整期間では1時間先の的中率54%でしたが、検証期間では51.5% (有意差なし) に落ちました。

### 15分足の検証

Yahoo Finance に残っている直近約60日分の15分足・5分足で同じ手順の検証を行い、[research/intraday.md](research/intraday.md) にまとめています (前半6割で設定を選び、後半4割で確認)。

- **方向:** 15分・1時間・4時間先とも、どの方法 (6モデル、直前の値動きの反転・継続など) も「変化なし」を有意に上回れませんでした。本番の15分足の予測も中心は現在値付近です。
- **レンジ:** 値動きの大きさの推定方法を24通り試し、調整期間で最もよかった「高値・安値の幅・時間帯60分刻み」を採用しました (検証期間では基準の方法と有意差なし)。レンジの形は t 分布 (自由度4〜5) です。
- **1時間足への応用:** 1時間足の予測で、各1時間の変動を15分足・5分足から測る方法も試しましたが、検証期間で改善しなかったため採用していません。

### バックテスト (毎サイクル更新)

サーバーは毎回の処理で、保存済みの価格を使ったバックテストも更新します。直近の各時点 (15分足は10日、1時間足は60日、日足は1年) で、**その時点までに確定した足だけ**を使って今のモデルで予測を作り直し、実際の値と比べます。中心値やレンジ幅の学習も本番と同じ規則で時系列順に再現し、その時点で結果が出ていた予測だけから学習させています。ニュースは当時の見出しを時点どおりに保存していないため使いません。新しい時点は毎回追加され、モデルのコードが変わると作り直されます。

台帳の実績 (結果が出る前に記録した予測) とは別物の参考値ですが、件数が多いため、レンジが名目どおり当たっているかを早い段階で確かめられます。2026年9月24日時点 (7ペア合計) の結果:

| 予測先 | 件数 | 50%レンジ | 80%レンジ | 95%レンジ | 方向の的中 |
|---|---|---|---|---|---|
| 15分足: 15分・1時間・4時間後 | 各約5,300 | 50%・50%・47% | 80%・80%・78% | 95%・94%・94% | 49%・49%・45% |
| 1時間足: 1・4・24時間後 | 各約7,200 | 52%・52%・55% | 80%・79%・77% | 94%・93%・90% | 50%・50%・53% |
| 日足: 1・5・10・20営業日後 | 各約1,800 | 53%・50%・46%・43% | 80%・79%・78%・77% | 93%・93%・92%・95% | 47%・51%・53%・55% |

レンジはおおむね名目どおりですが、先の長い予測ほど、相場が急に荒れた時期にはレンジが狭すぎる傾向があります (直近60日の日足10〜20営業日先の80%レンジは約64%)。方向の的中率は50%前後です。隣り合う時点の予測はほぼ同じ値動きで判定される (予測期間が重なる) ため、見かけの件数ほど確かではなく、偶然と区別できません。

再実行するには:

```bash
aifx research --download   # 過去の価格 (Yahoo Finance) と短期金利 (FRED) を data/history/ に保存
aifx research              # 検証して research/report.md と research/results.json を作成 (4並列で数分)
aifx research --intraday   # 15分足の検証 (research/intraday.md)
```

## 精度について

為替レートの方向を当てるのは非常に難しい (ランダムウォークに近い) ことが知られています。上記の20年以上の過去データでの検証でも、1時間〜20営業日先の方向を「変化なし」より安定して当てる方法は見つかりませんでした。そのため本番の予測は、実績で有効性が示されるまで中心値を「変化なし」付近に保ちます。成績をよく見せるためではなく、検証で最も誤差が小さかったためです。有効性が実績で示されれば、学習によって自動的に強く反映されるようになります。

一方、値動きの幅 (予測レンジ) は予測でき、検証で改善も確認できました。レンジが実際に何%当たっているかは、台帳の実績とバックテストの両方で公開しています。判断材料としては、中心値よりも予測レンジを重視してください。

## 構成

```
aifx/
  pipeline.py     1サイクルの処理 (取得 → 保存 → 判定 → 学習 → 予測 → 検証)
  forecaster.py   予測1件の計算 (サーバーと監査で同じ関数を使う)
  engine.py       予測期間・モデルの組み合わせ・ウォークフォワード検証
  models.py       6つの予測モデル
  volatility.py   予測レンジ (時間帯別の変動、週末、重要指標)
  learning.py     実績からの学習
  news.py         ニュース・経済指標の取得と分析、ニュース信号
  ledger.py       ハッシュ鎖の台帳と追記専用ファイル
  store.py        価格・ニュース・指標の保存
  audit.py        検証 (verify) と再計算による監査 (audit)
  track.py stats.py  実績の集計と統計検定
  backtest.py     毎サイクル更新するバックテスト (派生データ、台帳には含めない)
  history.py research.py research_intraday.py  過去データの取得と検証 (aifx research)
  analysis.py     市場分析 (通貨の強さ・値動きの荒さ・トレンドの状態)
  api.py site.py  API (JSON) とWebページの書き出し
  server.py       常駐サーバー (定期実行・API配信・更新依頼)
  templates/index.html  Webページ (APIを表示するだけ)
tests/            単体テスト、模擬セッション、不正の検出テスト
```

## 注意

予測は統計モデルによる参考値で、将来の値動きを保証するものではありません。投資判断はご自身の責任で行ってください。
