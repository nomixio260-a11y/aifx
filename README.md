# AIFX: 為替予測サーバー

主要7通貨ペア (USD/JPY, EUR/JPY, GBP/JPY, AUD/JPY, EUR/USD, GBP/USD, AUD/USD) の値動きを予測し続けるサーバーです。

- **予測はサーバーで計算します。** Webページはサーバーが公開するAPI (JSON) を表示するだけで、計算はしません。
- **予測は結果が出る前に台帳へ記録します。** 対象時刻が来たら自動で判定し、的中率・誤差・予測レンジの的中率を公開します。
- **自分の成績から学習します。** 判定済みの結果だけを使って、モデルの重み・信号の採用率・レンジの幅・ニュースの効き方を調整します。
- **売買プランを出します。** 過去データで取引として検証したルールから「買い / 売り / 見送り」、エントリー・利確・損切りの価格と決済の期限をチャートに表示し、そのシグナルも結果が出る前に台帳へ記録します。
- **ニュースと経済指標を自動で集めて分析します。** 各通貨への影響を判定し、予測と予測レンジに反映します。
- **成績をごまかせないようにしています。** 台帳はハッシュ鎖で改ざんを検出でき、先読みや判定の飛ばしはプログラムで自動検査します。

## 仕組み

```
      ┌──────────── サーバー (GitHub Actions 15分ごと / aifx serve) ────────────┐
      │ 1. 価格 (15分足・1時間足・日足)・ニュース・経済指標・短期金利を取得        │
      │ 2. 生データを追記専用ファイルに保存し、そのハッシュを台帳に記録              │
      │ 3. 対象時刻を過ぎた予測を判定 (結果を台帳に記録)                            │
      │ 4. 判定済みの結果から学習                                                   │
      │ 5. 新しい予測を発行 (台帳に記録)                                            │
      │ 6. 保存済みの価格でバックテストを更新 (新しい時点を追加)                    │
      │ 7. 台帳全体を検証し、抜き取りで予測を再計算                                 │
      │ 8. API (JSON) を書き出す                                                    │
      └──────────────────────────────┬────────────────────────────────────────────┘
                                     │ api/meta.json, api/pair/USDJPY.json, api/backtest.json …
                              ┌──────┴──────┐
                              │  Webページ   │  表示のみ。1分ごとに更新を確認
                              └─────────────┘
```

### 予測の種類

| 種類 | 起点 | 予測する時点 | 判定 |
|---|---|---|---|
| 超短期 (15分足) | 15分ごと、確定した15分足の終値 | 15分・1時間・4時間後 (15分足1・4・16本) | その時刻に確定していた15分足の終値 |
| 短期 (1時間足) | 毎時、確定した1時間足の終値 | 1・4・24時間後 (市場が開いている時間で数える) | その時刻に確定していた1時間足の終値 |
| 中期 (日足) | 毎日、確定した日足 (ロンドン時間の0時) | 1・5・10・20営業日後 | 同上 (1時間足) |

各予測には、中心値・20/40/50/60/80/95%の予測レンジ・上昇確率・価格の分布と、売買プラン (下記) が付きます。予測は次の足が確定する前に発行したものだけが有効で、サーバーの処理が遅れて次の足が確定してしまった場合、その起点の予測は出しません。

### モデルと学習

6つのモデル (ランダムウォーク、ドリフト、指数平滑、自己回帰、リッジ回帰、パターン類似) の予測を組み合わせ、次の4つを実績から学習します。設定値は、下記の「過去データによる検証」で古い期間だけを使って選び、新しい期間で効果を確かめたものです。

| 学習する値 | 意味 |
|---|---|
| モデルの重み | 誤差の小さいモデルを重く使う |
| 信号の採用率 (gain) | モデルの方向予測にどこまで従うか。過去の実績で有効性が示されない限り0に近く、予測は「変化なし」寄りになる |
| レンジ補正 (k) | 80%レンジに実際の値が約80%入るよう幅を調整 |
| ニュース係数 (β) | ニュース信号で予測をどれだけ動かすか |

学習には、予測の時点で判定が済んでいた結果だけを使います。始めは、各時点までのデータだけで行った過去データの検証 (ウォークフォワード) を事前情報にし、実績がたまるほど実績の比重が大きくなります。

予測レンジは次のように作ります。

- **15分足:** 各15分足の高値・安値の幅から値動きの大きさを測り、時間帯ごとの違い (1時間単位で推定)、週末、重要指標の発表予定を反映します。設定は直近約60日分の15分足で選び、後半の期間で確認しました (下記)。
- **1時間足:** 各1時間足の高値・安値の幅から値動きの大きさを測り、時間帯ごとの違い (ニューヨーク時間の曜日×時間、直近約1年。夏時間で動くロンドン・ニューヨークの取引時間とロールオーバー、静かな月曜のアジア時間や金曜の午後を反映)、週末の窓開けリスク、重要指標の発表予定を反映します。UTC の時間だけで測っていた前の版より、1時間先・4時間先の値動きの大きさの予測が調整期間・検証期間とも正確でした ([research/volatility.md](research/volatility.md))。
- **日足:** 1時間足から各日の値動きの大きさ (実現ボラティリティ) を測ります。1時間足が足りない日は日足の変化を使います。
- **レンジの形:** 為替の値動きは正規分布より裾が太い (大きな動きが起きやすい) ため、t 分布の形にしています。80%レンジの幅は実績で補正し、50%・95%レンジはこの形に従います。

### 売買プラン

予測の中心 (方向) には検証で優位性が見つかっていないため、「どこで買い、どこで利確・損切りするか」は、売買ルールを取引として過去データで検証して決めています ([research/trade.md](research/trade.md))。足の終値で注文し、ATR (最近の平均的な値幅) から決めた利確・損切りと最長保有期間で決済し、スプレッド・スリッページと保有中のスワップ (金利差から業者の取り分を引いたもの) を含めて損益を計算しました。1本の足の中で利確と損切りの両方に届いたときは損切りとしています。

| 時間足 | ルール | 利確・損切り・期限 | 検証期間の成績 (7ペア、コスト込み) |
|---|---|---|---|
| 1時間足 | 金利差が1%以上あり、過去120時間の値動きも同じ向きのときだけ、その方向に持つ | 利確 ATR×3、損切り ATR×3、最長24時間 | 2025/8〜2026/9: 1,425回、勝率55%、1回平均 +2.5 pips (t = 2.42) |
| 日足 | 金利差が2%以上ある通貨ペアを、スワップがつく方向に持つ | 利確 ATR×2、損切り ATR×4、最長5営業日 | 2017〜2026: 1,084回、勝率58%、1回平均 +19.4 pips (t = 2.04) |
| 15分足 | なし (検証に使える期間が約60日と短いため) | 買う場合・売る場合の目安 (ATR×3) のみ表示 | — |

試したルールは、金利差、モメンタム、金利差 + モメンタム、ブレイクアウト、移動平均の向き、RSI の逆張り、東京時間のレンジのロンドン時間ブレイクで、設定は古い期間 (日足 2002〜2016年、1時間足は前半6割) だけで選びました。調整期間と検証期間の両方で t ≥ 2 を満たしたルールはなく、上の2つは「両方の期間でプラス、検証期間で t ≥ 2」を満たしたため **参考シグナル (信頼度: 弱)** として成績を添えて表示しています。期待値は損切り幅の数%程度と小さく、急な円高などで損切りが続く時期もあります。

- 金利は FRED の短期金利を1日1回取得して台帳に保存し、研究と同じく公表の遅れを考慮して「その時点で知り得た値」だけを使います。
- 各予測の記録に売買プラン (方向・損切り・利確・期限) が入り、結果は保存済みの価格から判定します。抜き取り再計算 (`aifx audit`) では売買プランも当時のデータから作り直して照合します。
- 画面の「取引数量の目安」は、口座資金と1回で許せる損失 (%) から、損切り幅に合わせた数量を計算します。

### ニュース分析

- 取得元: Google ニュース検索 (日本語・英語の為替・中央銀行・米国指標・地政学)、FRB・ECB・日銀・英中銀・豪中銀の発表、ForexLive、Forex Factory の経済指標カレンダー
- 見出しごとに、USD・JPY・EUR・GBP・AUD それぞれへの影響 (−1 通貨安 〜 +1 通貨高) をキーワード分析 (日本語・英語) で判定します。分析はすべてサーバー内で行い、有料のAPIや外部の分析サービスは使いません。判定根拠となる語句は `aifx/news.py` で確認・調整できます。
- 「利上げ観測が後退」「利下げを急がず」「rate cut bets fade」「no rush to cut」のような否定・後退の表現は向きを反転させます。「ドル売り」「円買い」などの売買の表現や、「過度な変動をけん制」のような口先介入も判定します。
- 複数のサイトに配信された同じ記事は、見出しの文字の重なりでまとめ、1本として数えます (同じ記事が5サイトに載っても5倍にはなりません)。
- 通貨ごとの「ニュース圧力」は、新しい見出しほど重く (半減期 約8時間) 平均した値です。ペアの信号は「基軸通貨の圧力 − 決済通貨の圧力」です。
- 予測に使えるのは、**予測の起点時刻より前に取得・保存済みの見出しだけ**です。
- **見出しの読み取りの改善 (lexicon-v3):** 過去3か月分の見出し (GDELT の公開データ、約4万本) で分析を点検し、手で読んだ60本と照らして次を直しました: 戦争・政治の記事の「war」「tensions」などは、株・債券・為替・原油などの市場の語がある見出しでだけリスク回避と数える / 「停戦が崩れた」はリスク回避 / 新興国通貨の「対ドルで下落」から米ドルの動きを推定しない / 「上昇・下落」は通貨の名前にだけ付け、「円がドルに対して上昇」ではドルを逆向きに / 否定や期待の後退 (「didn't raise」「rate hike bets douse」「odds fall」) / 2026年の要人名 (Warsh、Bessent、片山など) と「eases」「edges lower」などの動詞。正しく読めた見出しは、修正を作った期間の30本で 11 → 20本、別の期間の30本で 9 → 18本になりました。
- **予測への使い方:** 同じ3か月で、記事の時刻を守ってニュースの信号と1・4・24時間後の値動きを比べたところ、期間によって向きが入れ替わり、方向の情報はありませんでした (GDELT のトーン・報道量も同じ。[research/news.md](research/news.md))。そのためニュースは予測の中心を初めからは動かさず (学習の初期値 0)、実績で効果がはっきりしたときだけ学習で反映します。ニュースは主に「いま何が起きているか」の表示に使います。

ニュースの取得先はすべて無料で公開されているRSSとカレンダーです。

## 成績をごまかせない仕組み

| ルール | どう守るか |
|---|---|
| 予測は結果が出る前に記録 | 予測は発行時に台帳へ追記。各記録は前の記録の SHA-256 ハッシュを含む (ハッシュ鎖) ので、書き換え・削除・並べ替えは検出される |
| 使ったデータを後から変えられない | 価格・ニュース・経済指標は追記専用ファイルに保存し、ローリングハッシュを台帳に記録 |
| 先読みしない | 予測に使えるのは起点時刻までに確定した価格と、起点時刻より前に保存済みのニュース・指標のみ。抜き取りで、当時のデータだけで予測を作り直し、同じ数字になるか確認 (`aifx audit`)。先読みしていれば一致しない |
| ニュースの取得時刻を偽れない | 各見出しの取得時刻は、それを保存したサイクルの時刻と一致しなければならない |
| 都合の悪い予測を判定から外せない | 対象時刻を過ぎ、データがそろった予測はすべて判定されていなければ検証エラー |
| 判定を早めたり、都合のよい価格を使えない | 判定は対象時刻の後、その時点で確定していた最新の足 (15分足の予測は15分足、それ以外は1時間足) の終値のみ |
| 対象時刻をずらせない | 対象時刻は取引カレンダーの規則どおりでなければ検証エラー |
| 売買シグナルを後から変えられない | 売買プランは予測と一緒に結果が出る前に記録。期限がルールどおりでない、損切り・利確がエントリーの逆側にある記録は検証エラー。抜き取り再計算で、当時の価格と金利から同じプランになるか確認 |
| 数字を盛れない | 成績は常に「予測しない (ランダムウォーク)」と同じ予測で比較し、95%信頼区間・有意性 (二項検定、Diebold-Mariano 検定)・Brierスコアを表示 |
| 履歴を書き換えられない | 台帳は GitHub の `ledger` ブランチに追記のみで push (force push しない)。サイクルごとに、前回の先頭記録が変わっていないことを確認 |

誰でも次のコマンドで検証できます。

```bash
git clone https://github.com/nomixio260-a11y/aifx && cd aifx
pip install -e .
git fetch origin ledger && git worktree add state origin/ledger
aifx verify --state state                    # ハッシュ鎖・データ・時刻・判定漏れ
aifx audit --state state --sample 20         # 予測を当時のデータで再計算
aifx audit --state state --external          # 保存した価格を取得し直した価格と照合
```

同じモデルで作られた予測だけが再計算の対象です (モデルのコードが変わると、以前の予測は対象外として件数を表示)。

### 予想ローソク足

チャートの「これから」の部分には、予想を範囲ではなくローソク足 (始値・高値・安値・終値) で描きます ([research/candles.md](research/candles.md))。

- **足の大きさ (高値−安値):** 今の値幅の水準 (値幅の指数加重平均) × その時間帯・曜日 (ニューヨーク時間。日足は曜日) のふだんの比率 (直近500回の中央値)。ロンドン・ニューヨーク時間や週明けの大きさの違いが反映されます。
- **足の形 (どこで引けるか、ヒゲの長さ):** 直近の値動きの形と時間帯が似た過去の局面を30個選び、その続きのうち最も代表的なもの (他との差が最も小さいもの) から取ります。
- **全体の水準:** 予想の中心 (検証で最も誤差が小さかった値) で終わるように傾けます。
- **陽線・陰線:** 15分足と1時間足では、時間帯の偏り (下記) が方向を示す足だけ、その向きにそろえ、チャートに ○ 印を付けます。それ以外の足の向きは似た局面の一例です。

履歴の後半4割 (1時間足 2025/8〜2026/9、15分足 2026/8/21〜9/24、日足 2020/1〜2026/9) で、各時点までのデータだけから作った予想ローソク足と実際の足を比べた結果 (7ペア):

| 時間足 | 足の大きさの誤差 (ATR 比) | 以前の版 (似た局面の中央値) | 陽線・陰線の的中率 | うち ○ 印の足 (割合: 的中率) |
|---|---|---|---|---|
| 15分足 (1・4・16本先) | −20%・−23%・−23% | −11%・−14%・−17% | 51.1%・50.1%・50.4% | 8%: 58.4%・57.3%・61.0% |
| 1時間足 (1・4・24本先) | −16%・−18%・−13% | −7%・−7%・−3% | 52.5%・50.4%・49.7% | 18%: 61.6%・55.0%・53.8% |
| 日足 (1・4・20本先) | −5%・−7%・−9% | +18%・+27%・+27% | 48.1%・50.5%・49.2% | — |

足の大きさは単純な平均値幅 (直近14本の ATR) より正確で、以前の版から改善しました。陽線・陰線が偶然 (50%) より当たるのは ○ 印の足だけで、それ以外の足の向きは当てにできません。サーバーは直近の成績 (15分足3日、1時間足20日、日足1年) も毎回計算して画面に表示します。

### 方向の予測 (時間帯の偏り)

方向を偶然より当てられるものを、論文などで報告されている為替の癖と、株価・金利など通貨ペアの外のデータも使って改めて検証しました ([research/direction.md](research/direction.md))。調整期間と検証期間の両方で効果があったのは **時間帯の偏り** だけです。

- **方法:** ロールオーバー (日付の切り替え) はニューヨーク時間17時に起きるため、時間帯はニューヨーク時間で数えます。1時間足は直近約1年の1時間足で「曜日×時間」と「時間」ごとに、15分足は直近約60日の15分足で「曜日×15分」と「15分」ごとに平均の値動きと t 値を測り、|t| ≥ 2 の足だけその向きに方向を示します。|t| ≥ 4 は **確度: 高** です (週明けの窓開けは除外、予測日の0時 UTC より前のデータのみ)。予測の中心には最初の1時間の分だけを加えます。
- **成績 (検証期間、次の足):**

  | | 方向を示した回の的中率 | うち確度: 高 | 確度: 高の割合 |
  |---|---|---|---|
  | 1時間足 (検証 2025/8〜2026/9) | 61.1% (8,493回) | **79.8%** (1,069回) | 約2% |
  | 1時間足 (調整 〜2025/8) | 56.3% (9,296回) | **74.9%** (899回) | 約2% |
  | 15分足 (直近約60日) | 56.6% (2,245回) | **85.7%** (266回) | 約1% |

  UTC で数えていた前の版 (56.8%) より当たります。最初の1時間の向きは4時間後・24時間後には当たらず (約50%)、中心への反映は最初の1時間に限っています。すべての予測を平均した方向の的中率は、方向を示さない時間が大半のため 50% 台前半のままです。
- **注意:** 偏りの大部分はニューヨーク時間17時 (日本時間の朝6〜7時) のロールオーバー前後です。この時間はスワップの付与に合わせて価格がずれ (金利の高い通貨を買う方向のペアが下がり、水曜日はスワップ3日分で下げが大きく、金曜日は逆向き)、スプレッドも広がります。表示される価格の方向としては当たりますが、売買の利益にはなりにくいものです。
- **ディープラーニング:** 直近64本の値動き・値幅・他の6ペアの動き・ニューヨーク時間の時刻を読み込む 1次元CNN+GRU と Transformer を、毎月学び直すウォークフォワードで検証しました ([research/dl.md](research/dl.md))。次の1時間の AUC は 0.530 (0.5 がでたらめ) で、力のほとんどは時間帯の偏りの再発見でした (時刻の入力を外すと 0.51 に下がる)。自信のある上位1〜2%で検証期間 72〜74% になる組み合わせもありましたが、調整期間では 56〜58%、乱数の種を変えると 63〜65% で再現せず、同じ割合に絞った時間帯の偏り (上位1%: 82%、上位2%: 77%) にどの段階でも及ばなかったため、本番には入れていません。4時間・24時間先と日足でも安定した力はありませんでした。
- **効果がなかったもの:** 自国の取引時間に通貨が弱くなる癖、五十日の仲値、S&P500先物の動きの波及、月末の株式ヘッジの調整、米2年金利の変化、株価のモメンタム、金利差・モメンタム (4時間・24時間先、日足を含む)。
- **データの注意:** Yahoo の為替日足の終値は、2011年ごろから「その日の始め (0時 UTC) の価格」になっています。株価との比較で見かけ上 59% 当たる結果が出ましたが、時刻を正しくそろえると消えました。日足の予測は、基準価格と答え合わせに1時間足の実際の価格を使っているため、この影響を受けません。
- 画面では、予想ローソク足の ○ 印 (● は確度: 高)、チャート下の「次の1時間: 上がりやすい / 下がりやすい (確度と検証での的中率) / 方向の根拠なし」、実績タブの「時間帯の偏りで方向を示した回」「うち確度が高い回」の的中率で確認できます。

## Webで見る

画面は5つのタブに分かれています。スマホでは画面下のタブで切り替えます。

| 実績 | 台帳に記録した予測の的中率、ランダムウォークとの比較、50/80/95%レンジの的中率、確率の信頼性。その下にバックテスト (全ペア・ペア別) の成績と推移 |
| ニュース | 通貨ごとのニュース圧力と推移、ペア別の信号、経済指標カレンダー、見出しと分析結果 (同じ記事はまとめて表示) |

スマホではチャートを指でなぞってもページがスクロールするようにし、表示期間はボタンで切り替えます。パソコンではドラッグで移動、Ctrl+ホイールで拡大できます。予想ローソク足・移動平均・RSI はチャートの下のボタンで表示を切り替えられます。

日足のチャートの実際のローソク足は、1時間足からロンドン時間の1日ごと (予測の起点と同じ区切り) に作り直して表示します。Yahoo の為替日足は終値が「その日の始めの価格」になっていて、高値・安値も途中で止まっていることがあるためです (予測と売買プランの計算は保存した日足のままで、作り直した日足で予測の精度は変わりませんでした)。

市場分析は値動きの「現在の状態」の説明で、予測ではありません。予想の分布と確率は、サーバーが予測と同じ分布 (t 分布) から計算したもので、Webページは表示するだけです。

- **自分のサーバー:** 下記の `aifx serve` または Docker。ページ上の「今すぐ更新」でサーバーに更新を依頼できます。

## GitHub での運用

- `.github/workflows/server.yml` が15分ごとに1サイクルを実行し、台帳を `ledger` ブランチに追記して、Pages が有効ならWebページを公開します。デフォルトブランチへのコードの push でもすぐ実行されます。GitHub の定期実行は混雑時に遅れたり間引かれたりするため、15分足の予測は実行された回の分だけ発行されます。
- バックテストの計算結果は台帳ではなく派生データなので、Actions のキャッシュで実行間に引き継ぎ、毎回は新しい時点だけを計算します (キャッシュが消えても次の実行で作り直します)。
- `ledger` ブランチにブランチ保護 (force push の禁止) を設定すると、履歴の書き換えをGitHub側でも防げます。
- `.github/workflows/ci.yml` がテスト (不正の検出テストを含む) を実行します。

## 過去データによる検証

2002年からの日足 (7ペア) と直近約2年分の1時間足で、**各時点ではその時点までのデータだけで予測する**検証 (ウォークフォワード) を行い、結果を [research/report.md](research/report.md) にまとめています。台帳の実績とは別の、事前の検証です。

- 設定値や係数は古い期間 (日足は2002〜2016年、1時間足は前半6割) だけで決め、新しい期間 (日足は2017〜2026年、1時間足は後半4割) の成績で採否を判断しました。検証期間のデータは設定選びに使っていません。
- 金利差 (キャリー) には FRED の短期金利を使い、公表の遅れを考慮して当時知り得た値だけを使いました。
- 試した方法: 6モデルとその組合せ、金利差、モメンタム、時間帯の癖、直前の値動き、値動きの大きさの推定方法 (EWMA の設定、高値・安値の幅、1時間足からの実現ボラティリティ)、レンジの形 (正規分布・t 分布)。

**結果:**

| 対象 | 検証期間の結果 | 本番への反映 |
|---|---|---|
| 方向 (中心値) | どの方法も「変化なし」を有意に上回れず。6モデルの単純平均は有意に悪化 | 方向予測への追従を強く抑える (λ 11→50)。日足10〜20営業日先の悪化幅が約1/4に |
| 1時間足のレンジ | 高値・安値の幅を使うと 1・4時間先の CRPS が有意に改善 | 採用 |
| 日足のレンジ | 1時間足から測る実現ボラティリティで 1・5営業日先が有意に改善 | 採用 |
| レンジの形 | 50%レンジの的中 55%→52%、95%レンジ 93%→95% (1時間足) と名目値に近づく | t 分布を採用 |

さらに、予測レンジについて5つの案 (補正に使う実績の期間、上下で幅の違うレンジ、VIX による調整、週末・曜日の補正、時間帯ごとの変動の推定方法) も同じ手順で試しましたが、改善はどれも0.2%程度以下で、採用していません。

調整に使った期間で成績を測ると実力以上に見えます。例えば「時間帯ごとの値動きの癖」は、調整期間では1時間先の的中率54%でしたが、検証期間では51.5% (有意差なし) に落ちました。

### 15分足の検証

Yahoo Finance に残っている直近約60日分の15分足・5分足で同じ手順の検証を行い、[research/intraday.md](research/intraday.md) にまとめています (前半6割で設定を選び、後半4割で確認)。

- **方向:** 15分・1時間・4時間先とも、どの方法 (6モデル、直前の値動きの反転・継続など) も「変化なし」を有意に上回れませんでした。本番の15分足の予測も中心は現在値付近です。
- **レンジ:** 値動きの大きさの推定方法を24通り試し、調整期間で最もよかった「高値・安値の幅・時間帯60分刻み」を採用しました (検証期間では基準の方法と有意差なし)。レンジの形は t 分布 (自由度4〜5) です。
- **1時間足への応用:** 1時間足の予測で、各1時間の変動を15分足・5分足から測る方法も試しましたが、検証期間で改善しなかったため採用していません。

### バックテスト (毎サイクル更新)

サーバーは毎回の処理で、保存済みの価格を使ったバックテストも更新します。直近の各時点 (15分足は10日、1時間足は60日、日足は1年) で、**その時点までに確定した足だけ**を使って今のモデルで予測を作り直し、実際の値と比べます。中心値やレンジ幅の学習も本番と同じ規則で時系列順に再現し、その時点で結果が出ていた予測だけから学習させています。ニュースは当時の見出しを時点どおりに保存していないため使いません。新しい時点は毎回追加され、モデルのコードが変わると作り直されます。

台帳の実績 (結果が出る前に記録した予測) とは別物の参考値ですが、件数が多いため、レンジが名目どおり当たっているかを早い段階で確かめられます。2026年9月24日時点 (7ペア合計) の結果:

| 予測先 | 件数 | 50%レンジ | 80%レンジ | 95%レンジ | 方向の的中 |
|---|---|---|---|---|---|
| 15分足: 15分・1時間・4時間後 | 各約5,300 | 50%・50%・47% | 80%・80%・78% | 95%・94%・94% | 49%・49%・45% |
| 1時間足: 1・4・24時間後 | 各約7,200 | 52%・52%・55% | 80%・79%・77% | 94%・93%・90% | 50%・50%・53% |
| 日足: 1・5・10・20営業日後 | 各約1,800 | 53%・50%・46%・43% | 80%・79%・78%・77% | 93%・93%・92%・95% | 47%・51%・53%・55% |

レンジはおおむね名目どおりですが、先の長い予測ほど、相場が急に荒れた時期にはレンジが狭すぎる傾向があります (直近60日の日足10〜20営業日先の80%レンジは約64%)。方向の的中率は50%前後です。隣り合う時点の予測はほぼ同じ値動きで判定される (予測期間が重なる) ため、見かけの件数ほど確かではなく、偶然と区別できません。

## 精度について

為替レートの方向を当てるのは非常に難しい (ランダムウォークに近い) ことが知られています。上記の20年以上の過去データでの検証でも、1時間〜20営業日先の方向を「変化なし」より安定して当てる方法は見つかりませんでした (機械学習・ディープラーニング、株価・金利などの外部データでも同じ、[research/ml.md](research/ml.md)、[research/dl.md](research/dl.md)、[research/direction.md](research/direction.md))。例外は「時間帯の偏り」で、1時間足の次の1時間は、方向を示した回 (およそ6回に1回) に限り約61%、確度が高い回 (約2%) は約80%当たります (主にロールオーバー前後で、売買の利益にはなりにくいもの)。そのため本番の予測は、この偏りを除いて、実績で有効性が示されるまで中心値を「変化なし」付近に保ちます。成績をよく見せるためではなく、検証で最も誤差が小さかったためです。有効性が実績で示されれば、学習によって自動的に強く反映されるようになります。

一方、値動きの幅 (予測レンジ、予想ローソク足の大きさ) は予測でき、検証で改善も確認できました。レンジが実際に何%当たっているかは、台帳の実績とバックテストの両方で公開しています。判断材料としては、中心値よりも予測レンジを重視してください。
